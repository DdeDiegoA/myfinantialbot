# MyFinancialBot

A grounded RAG assistant for the Colombian DIAN 2025 renta (income tax) declaration rules. Answers cite their source document; if the corpus doesn't cover the question, it says so instead of guessing.

Built for Reto 3 EPAM ("IA con Criterio") — the evaluation criterion is *not hallucinating*, so that guarantee is enforced in code (a hard threshold gate), not left to a prompt instruction.

## Quickstart

```bash
pip install -r requirements.txt && python ingest.py
python rag.py "¿Quiénes deben declarar renta en 2025?"
```

Before either command: copy `.env.example` to `.env` and set `LLM_PROVIDER` / `LLM_MODEL` / `LLM_API_KEY`. `ingest.py` doesn't need it (embedding is local); `rag.py` does, for the generation call.

## Architecture

```
                     ingest.py (offline, run once)
  docs/dian/*.md  ──chunk──▶  MiniLM embed (CPU)  ──▶  index.faiss + chunks.json

                     rag.py / serve.py (per query)
  question ──▶ MiniLM embed ──▶ FAISS top-k search ──▶ score
                                                          │
                                        ┌─────────────────┴─────────────────┐
                                        │                                   │
                                score < threshold                   score >= threshold
                                        │                                   │
                                        ▼                                   ▼
                         "I don't have that information."      build cited prompt ──▶ llm.py
                              (no LLM call, no cost)                   │
                                                                        ▼
                                                        PROVIDERS[LLM_PROVIDER] HTTP call
                                                        (nvidia / openrouter / anthropic /
                                                              openai / custom — from .env)
                                                                        │
                                                                        ▼
                                                         {answer, sources: [source_file...]}
```

`rag.py` (CLI) and `serve.py` (Bonus B FastAPI endpoint) both call the same `answer_question()` in `rag.py`, so local and public behavior can't drift apart.

## Why Nvidia as default, OpenRouter as fallback

`llm.py` is a plain dict of `{provider: base_url}` (openrouter / nvidia / anthropic / openai / custom) plus one OpenAI-compatible HTTP call — every provider speaks close enough to the same `/chat/completions` shape that a class hierarchy or plugin system would be pure overhead for 4-5 near-identical HTTP calls.

Nvidia is the default because its cost/latency (~10.3s on the benchmarked model) was already tested and preferred over alternatives. Known risk: Nvidia's direct endpoint has returned HTTP 500 intermittently in prior testing. Mitigation is a one-line config change, not a code change — `.env.example` ships the OpenRouter (`deepseek/deepseek-chat`) equivalent commented out directly below the Nvidia config, so recovering from the bug during a live demo is `LLM_PROVIDER=openrouter` and nothing else.

## Why local FAISS + MiniLM, not a hosted vector DB

The corpus is 8-15 small public DIAN documents — nowhere near the scale a hosted vector DB (Pinecone, Weaviate, etc.) is built for. A hosted DB would add a signup step and a network dependency for whoever clones the repo, breaking the "2 commands, no infra" promise this project is scored on. `all-MiniLM-L6-v2` embeds this corpus on CPU in milliseconds, and the FAISS index is one local file (`index.faiss`, generated by `ingest.py` and gitignored alongside `chunks.json` — reproducible from `docs/dian/*.md` in seconds, so there's nothing to keep in sync by committing it) — no service to provision, no account to create.

### Adding new corpus data

Drop a new `.md` file into `docs/dian/` (add its source URL to `docs/dian/SOURCES.md`), then re-run `python ingest.py`. `docs/dian/` is the only directory `ingest.py` reads — it never touches `docs/context.md`, `docs/decisions.md`, `docs/skills.md`, or the `docs/architecture|specs|design-system/` subdirectories, which are protto's own project-scaffold docs, not RAG corpus content.

## Anti-hallucination contract

- `RELEVANCE_THRESHOLD` (env `RAG_THRESHOLD`, default `0.35`) gates every query in code, before any LLM call — an out-of-corpus question never reaches the model, it can't rationalize its way past a check that happens before it's invoked.
- Below threshold: exact fixed string `"I don't have that information."`, no `sources`, no LLM cost.
- Above threshold: the system prompt in `rag.py` instructs the model to answer only from the retrieved context, cite `[source_file]` inline, and flag partial coverage — and the response always carries a non-empty `sources` list.

## DIAN sources in the corpus

All documents live under `docs/dian/*.md`, cited from official DIAN pages/PDFs; full mapping in `docs/dian/SOURCES.md`. Topics covered: what the UVT is and its 2025 value, the six conditions that trigger a filing obligation (and their inverse — who's exempt), the patrimonio bruto / ingresos brutos / credit-card-spend / bank-deposit / total-purchases UVT thresholds for AG 2025, VAT-responsible status as a filing trigger, the legal definition of patrimonio bruto (Estatuto Tributario Art. 261), and the filing deadline calendar by cédula digit.

## Project layout

```
docs/dian/*.md   DIAN source corpus (see docs/dian/SOURCES.md) — the only dir ingest.py reads
ingest.py        chunk → embed → build index.faiss + chunks.json (offline, CPU-only, gitignored output)
rag.py           retrieval + anti-hallucination gate + answer_question(); also the CLI
llm.py           provider-agnostic completion call, config-driven via .env
.env.example     documented provider config, no real keys
eval.py          Bonus A eval harness against tests/qa.json, outputs a /100 score
serve.py         [planned, Bonus B] FastAPI /ask /health — imports rag.py, no local generation
```

## Notes

- `.env` must exist (copied from `.env.example` and filled in) before running `rag.py` — `ingest.py` runs without it.
- No API key is ever hardcoded or committed; `provider-config` spec requires config-only credentials (see `openspec/changes/rag-dian-core/specs/`).
- Full requirement specs (corpus ingestion, query/retrieval, anti-hallucination, provider config, eval harness, public endpoint) live under `openspec/changes/rag-dian-core/specs/`; design rationale and rejected alternatives in `openspec/changes/rag-dian-core/design.md`.
